# `CU-SAL-09` — Crear salida de merma

| Sección | Información relevante |
| --- | --- |
| Identificador | `CU-SAL-09` |
| Nombre | Crear salida de merma. |
| Actor | Personal de almacén o Administrador del sistema. |
| Disparador | Selecciona la acción principal para crear una salida desde `CU-SAL-08` Consultar salidas de merma. |
| Precondiciones | 1. El actor inició sesión.<br>2. El actor cuenta con el permiso de alta.<br>3. Existen los datos relacionados requeridos para completar el registro. |
| Flujo principal | 1. **Actor:** abre «Agregar salida de merma» **(ver E1)**.<br>2. **Nexus:** muestra el formulario y carga clientes, asesores, áreas, solicitantes y mermas disponibles.<br>3. **Actor:** selecciona cliente, asesor, área y solicitante; captura número de proyecto, fecha y hora de solicitud y observaciones; selecciona una merma, captura su cantidad y selecciona «Agregar» **(ver A1)**.<br>4. **Nexus:** valida los datos del renglón y lo muestra en la tabla de detalles. Si la merma ya estaba agregada, reemplaza su cantidad por la más reciente, sin sumarla.<br>5. **Actor:** repite la adición para cada merma necesaria, revisa los renglones de la tabla y selecciona «Guardar».<br>6. **Nexus:** valida participantes, relaciones, mermas y cantidades y rechaza cualquier carga que todavía contenga una merma repetida **(ver A2)**; crea la salida pendiente sin descontar existencias, actualiza la tabla de salidas y confirma. Además, guarda los cambios de la operación en la base de datos **(ver EBD)**. |
| Flujos alternativos | **A1 — Datos inválidos (después del paso 3):**<br>1. **Nexus:** valida la información capturada, detecta campos incompletos, formatos incorrectos, relaciones no permitidas o cantidades fuera de las reglas del caso y los señala sin registrar cambios.<br>2. **Actor:** corrige la información indicada y vuelve a confirmar; continúa en el paso 3 del flujo principal.<br>**A2 — Merma inactiva (después del paso 6):**<br>1. **Actor:** revisa la merma inactiva señalada por Nexus.<br>2. **Nexus:** conserva el formulario sin crear la salida, detalles ni cambios de stock.<br>3. **Actor:** selecciona una merma activa y vuelve a confirmar; continúa en el paso 3 del flujo principal. |
| Excepciones | **E1 — Acceso rechazado (después del paso 1):**<br>1. **Nexus:** comprueba las precondiciones y la autorización, determina que alguna no se cumple y rechaza la solicitud sin modificar datos ni exponer información no autorizada; comunica el motivo.<br>2. **Actor:** reconoce el rechazo; termina el caso de uso.<br>**EBD — Error de base de datos o de conexión (durante el paso 6 del flujo principal):**<br>1. **Nexus:** detecta que no puede consultar o guardar la información, revierte cualquier cambio parcial y comunica que la operación no se completó.<br>2. **Actor:** recibe el aviso, conserva los datos capturados cuando existe un formulario y decide reintentar más tarde o terminar el caso de uso. |
| Postcondiciones (éxito y fallo) | 1. **Éxito:** La salida de merma queda registrada en estado pendiente.<br>2. **Éxito:** Las existencias permanecen sin cambios hasta el surtimiento.<br>3. **Fallo:** Un rechazo no debe producir cambios parciales ni exponer información no autorizada. |
| Requisitos relacionados | `RF-WST-002`. |
