# `CU-SAL-02` — Crear salida de material

| Sección | Información relevante |
| --- | --- |
| Identificador | `CU-SAL-02` |
| Nombre | Crear salida de material. |
| Actor | Personal de almacén o Administrador del sistema. |
| Disparador | Selecciona la acción principal para crear una salida desde `CU-SAL-01` Consultar salidas de material. |
| Precondiciones | 1. El actor inició sesión.<br>2. El actor cuenta con el permiso de alta.<br>3. Existen los datos relacionados requeridos para completar el registro. |
| Flujo principal | 1. **Actor:** abre «Agregar salida de material» **(ver E1)**.<br>2. **Nexus:** muestra el formulario y carga clientes, asesores, áreas, solicitantes y materiales disponibles.<br>3. **Actor:** selecciona cliente —o elige **Nuevo cliente** para iniciar `CU-CAT-06`—, asesor, área y solicitante; captura número de proyecto, fecha y hora de solicitud y observaciones; selecciona un material y proveedor, captura su cantidad y selecciona «Agregar» **(ver A1)** **(ver A3)**.<br>4. **Nexus:** valida los datos del renglón y lo muestra en la tabla de detalles. Si ya existía la misma combinación material-proveedor, reemplaza su cantidad por la más reciente, sin sumarla.<br>5. **Actor:** repite la adición para cada material necesario, revisa los renglones de la tabla y selecciona «Guardar».<br>6. **Nexus:** valida participantes, relaciones, materiales y cantidades **(ver A2)**; crea la salida pendiente sin descontar existencias, actualiza la tabla de salidas y confirma. Además, guarda los cambios de la operación en la base de datos **(ver EBD)**. |
| Flujos alternativos | **A1 — Datos inválidos (después del paso 3):**<br>1. **Nexus:** valida la información capturada, detecta campos incompletos, formatos incorrectos, relaciones no permitidas o cantidades fuera de las reglas del caso y los señala sin registrar cambios.<br>2. **Actor:** corrige la información indicada y vuelve a confirmar; continúa en el paso 3 del flujo principal.<br>**A2 — Material o proveedor inactivo (después del paso 6):**<br>1. **Actor:** revisa los recursos inactivos señalados por Nexus.<br>2. **Nexus:** conserva el formulario sin crear la salida, detalles ni cambios de stock.<br>3. **Actor:** selecciona recursos activos y vuelve a confirmar; continúa en el paso 3 del flujo principal.<br>**A3 — Cliente no catalogado (después del paso 3):**<br>1. **Actor:** escribe el cliente que no existe y selecciona **Nuevo cliente** desde el selector de la salida.<br>2. **Nexus:** inicia `CU-CAT-06` y abre el formulario reutilizable sin permitir el acceso al listado independiente.<br>3. **Nexus:** al completar el alta, agrega y selecciona el cliente creado en la salida.<br>4. **Actor:** continúa capturando el encabezado y los detalles en el paso 3 del flujo principal. |
| Excepciones | **E1 — Acceso rechazado (después del paso 1):**<br>1. **Nexus:** comprueba las precondiciones y la autorización, determina que alguna no se cumple y rechaza la solicitud sin modificar datos ni exponer información no autorizada; comunica el motivo.<br>2. **Actor:** reconoce el rechazo; termina el caso de uso.<br>**EBD — Error de base de datos o de conexión (durante el paso 6 del flujo principal):**<br>1. **Nexus:** detecta que no puede consultar o guardar la información, revierte cualquier cambio parcial y comunica que la operación no se completó.<br>2. **Actor:** recibe el aviso, conserva los datos capturados cuando existe un formulario y decide reintentar más tarde o terminar el caso de uso. |
| Postcondiciones (éxito y fallo) | 1. **Éxito:** La salida de material queda registrada en estado pendiente.<br>2. **Éxito:** Las existencias permanecen sin cambios hasta el surtimiento.<br>3. **Fallo:** Un rechazo no debe producir cambios parciales ni exponer información no autorizada. |
| Requisitos relacionados | `RF-ISS-004`, `RN-004`, `RN-019`, `RN-023`. |
