# 11. Criterio para mantener este documento

Se revisa la visión cuando cambia el problema, un objetivo, una parte interesada, el
alcance, una dependencia, una restricción o una decisión pendiente. Si sólo cambia una
realización técnica, se revisa su impacto y se actualiza el artefacto propietario.

Un cambio documental debe conservar:

1. Objetivos y alcance coherentes entre sí y enlazados con los grupos de la SRS.
2. Terminología consistente con el glosario y distinción entre capacidad vigente y propuesta.
3. Decisiones pendientes con su riesgo; una decisión resuelta requiere referencia al
   acuerdo, responsable y evidencia en la incidencia o solicitud de cambio.
4. Necesidades de calidad sin umbrales inventados; un compromiso nuevo requiere contexto,
   medida, responsable y aceptación antes de incorporarlo como requisito normativo.
5. Fuentes Markdown y paquetes exportados legibles, con referencias válidas.

Desarrollo mantiene la correspondencia técnica y las comprobaciones documentales;
la autoridad de aceptación funcional se designa según el capítulo 10. El historial de
Git registra cambios y revisión técnica; no sustituye el acuerdo de negocio.
