# `CU-SAL-02` — Crear salida de material

| Sección | Información relevante |
| --- | --- |
| Identificador | `CU-SAL-02` |
| Nombre | Crear salida de material. |
| Actor | Usuario autorizado de área operativa, Personal de almacén o Administrador del sistema. |
| Disparador | Selecciona la acción principal para crear una salida desde `CU-SAL-01` Consultar salidas de material. |
| Precondiciones | 1. El actor inició sesión.<br>2. El actor cuenta con el permiso de alta.<br>3. Existen los datos relacionados requeridos para completar el registro.<br>4. El área del documento y el área de destino pertenecen al alcance autorizado de la sesión. |
| Flujo principal | 1. **Actor:** selecciona **Nueva salida** **(ver E1)**.<br>2. **Nexus:** abre el formulario con clientes, áreas autorizadas y la sección **Agregar detalle**. Si la cuenta sólo tiene un área activa disponible, la selecciona y bloquea el campo.<br>3. **Actor:** selecciona Cliente y elige o revisa el Área de destino **(ver A3)**.<br>4. **Nexus:** carga Asesor según el cliente y Solicitante según el área; al cambiar las selecciones limpia los datos dependientes. Para GPG INTERNO sugiere el proyecto configurado para el área.<br>5. **Actor:** selecciona asesor y solicitante, completa proyecto, fecha y hora y observaciones; selecciona un material y su proveedor, captura la cantidad y pulsa **Agregar** **(ver A1)**.<br>6. **Nexus:** valida el detalle y lo incorpora a la tabla; si ya existe la misma combinación material-proveedor, acumula cantidad y conversión; otro proveedor conserva otra fila.<br>7. **Actor:** repite los pasos 5 y 6 para otros detalles, revisa las filas y pulsa **Guardar**.<br>8. **Nexus:** valida participantes, área, proyecto, estado activo y cantidades de materiales **(ver A2 y A4)**; registra la salida pendiente sin descontar existencias, actualiza el listado y muestra la confirmación **(ver EOP)**. |
| Puntos de extensión | Cliente no catalogado: paso 3, condición **Registrar cliente** y permiso de alta, extensión `CU-CAT-06`, flujo A3; retorna al paso 4. |
| Flujos alternativos | **A1 — Detalle inválido (después del paso 5):**<br>1. **Nexus:** señala la selección o cantidad inválida y no agrega el detalle; conserva las filas preparadas.<br>2. **Actor:** corrige el detalle y pulsa **Agregar**; continúa en el paso 6 del flujo principal.<br>**A2 — Recurso inactivo (durante el paso 8):**<br>1. **Nexus:** informa el recurso inactivo y conserva la captura sin registrar la salida ni modificar inventario.<br>2. **Actor:** retira las filas rechazadas con **Eliminar detalle** y prepara detalles con recursos activos; continúa en el paso 5 del flujo principal.<br>**A3 — Cliente no catalogado, con permiso de alta (durante la selección del paso 3):**<br>1. **Actor:** busca el cliente y pulsa **Registrar cliente**.<br>2. **Nexus:** conserva la captura principal y abre el formulario de `CU-CAT-06` con el contexto de la operación.<br>3. **Actor:** completa el alta de cliente mediante ese caso o cancela el formulario auxiliar.<br>4. **Nexus:** retoma el formulario de origen; selecciona el registro confirmado si está activo y conserva la selección previa si se cancela o se crea inactivo. Continúa en el paso 4 del flujo principal sin guardar el documento principal.<br>**A4 — Encabezado o conjunto de detalles inválidos (durante el paso 8):**<br>1. **Nexus:** señala participantes, área, proyecto, fecha o detalles que deben corregirse y conserva el formulario sin registrar la salida.<br>2. **Actor:** corrige los datos o completa las filas requeridas y pulsa **Guardar**; continúa en el paso 8 del flujo principal. |
| Excepciones | **E1 — Acceso rechazado (después del paso 1 o durante el paso 8):**<br>1. **Nexus:** rechaza la solicitud, comunica el motivo y no presenta información ni ejecuta cambios fuera de la autorización del actor; termina el caso de uso.<br>**EOP — Operación no confirmada (durante el paso 8):**<br>1. **Nexus:** comunica que no pudo confirmar el resultado y no anuncia éxito; conserva la captura cuando el formulario sigue disponible. Termina el caso de uso. |
| Postcondiciones (éxito y fallo) | 1. **Éxito:** La salida de material queda registrada en estado pendiente.<br>2. **Éxito:** Las existencias permanecen sin cambios hasta el surtimiento.<br>3. **Fallo:** Un rechazo no debe producir cambios parciales ni exponer información no autorizada. |
| Requisitos relacionados | `RF-ISS-007`, `RF-ISS-004`, `RN-004`, `RN-019`, `RN-023`, `RN-035`. |
